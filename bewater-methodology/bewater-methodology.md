## 1. 全景：一张图看懂 bewater

bewater 把"创新"当作**可被种子化、打磨、测试、验证、交付、增长**的 predictable 过程——挑战"创新是随机的"这个信念。架构分三层：

```
┌──────────────────────────────────────────────────────────────────────────┐
│  哲学层  水的五重性：渗透（Money+Magic）· 流动（假设驱动）· 适应（Strategy=Choice）     │
│         · 分流（广发散窄收敛）· 成势（归纳+消除法）                               │
├──────────────────────────────────────────────────────────────────────────┤
│  流程层  Start（Immersion）│ 4 模块 × 8 Stage │ 4 道门 │ 3 种循环                │
├──────────────────────────────────────────────────────────────────────────┤
│  知识层  产物链血缘 · 假设账本 · 知识库留底 · 交接协议 · 双学习环                  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 1.1 全链路：决策段 vs 执行段

```
┌──────── 决策段：管理不确定性 ────────┐ ┌──── 执行段：管理确定性交付 ────┐
│ Strategy 战略定位   Concept 概念创新  │ │ Realization 落地实现  Operation 市场运营│
│                                      │ │                                  │
│ Immersion → Discover ─→ Define ─G1─ Ideate ─→ Shape ─G2─               │ │ Design ─→ Build ─G3─ Launch ─→ Grow ─G4⟳ │
│ 目标对齐     发现洞察    战略定义     探索概念   方案定义                 │ │ 设计方案   系统构建  部署发布   增长sustain│
└──────────────────────────────────────┘ └──────────────────────────────────┘
                    外环：Grow 的增长洞察 ⟶ 下一代 Immersion / Discover ◀──────
```

- **G1 战略门**（Define → Ideate，判断题）：方向值得投入探索资源吗？
- **G2 概念门**（Shape → Design，举证题，**全流程最重**）：概念被验证到值得投入建设资源了吗？本质是立项决策。
- **G3 发布门**（Build → Launch，清单题）：达到进入市场的标准了吗？
- **G4 经营评审**（Grow 段周期性）：继续投入 / 维持收割 / 退役？

> 意象：决策段如水在山间（流向未定，探索），执行段如水入平原（河道已定，工程输送）。此后正文一律用 Stage 直白命名。

### 1.2 决策段 vs 执行段：两套管理逻辑（核心）

| | 决策段（Strategy + Concept） | 执行段（Realization + Operation） |
|---|---|---|
| 管理对象 | **不确定性**（假设账本） | **确定性交付**（范围 / 质量 / 进度） |
| 度量 | 假设验证速度 | 交付速度与质量 |
| 文化 | 推翻重来是常态，**Kill 是成功** | 反复摇摆战略是最大浪费 |
| 门性质 | G1 判断题 / G2 举证题 | G3 清单题 |

> ⚠️ 最常见的组织失配：**用执行段思维管决策段**（对探索工作要求排期与确定性），或**用决策段思维管执行段**（Build 阶段还在反复重议战略）。两段的管理逻辑必须分开。

### 1.3 非线性：线性骨架 + 循环 + 分支

八 Stage 看似一条直线，但实际工作方式是**非线性**的：

- **小循环 · 迭代**（常态）：模块内 / 相邻 Stage（如 Design↔Build、Ideate↔Shape）高频来回，不经过门，是工作节奏。
- **大循环 · 回退**（中频）：跨模块向上游回溯，**必须经过原门重新裁决**——当已被验证的前提失效时触发。
- **外环 · 代际**（低频）：Grow 的结构性增长洞察，喂回下一代 Immersion / Discover。

> 线性骨架保证"会往前走、会交付"（每段有门）；循环 + 分支保证"会修正、不会一条错路走到底"。

## 2. 哲学层：水的五重性（第一性原则）

> 这一章用「水」做哲学记忆抓手。五性映射到五条方法论原则；记住隐喻，就记住原则。Stage 的水名对照见 §2.6。

### 2.1 渗透 Permeate —— Money + Magic 双面浸润

水会渗进每一条缝隙。好的创新同样要浸润两面：

| | 是什么 | 问什么 |
|---|---|---|
| **Magic** | 对用户处境与渴望的共情深度 | 你真的懂这个用户吗？他的处境、他的痛、他的渴望？ |
| **Money** | 商业逻辑成不成、怎么赚 | 这生意成不成？怎么赚、怎么持续赚？ |

⚠️ **Magic 不是"用户愿不愿买单"**（那是下游验证），而是更上游的**共情深度**。单面倾斜是最常见的死法：全是 magic 的产品感动自己，全是 money 的产品没人爱。**渗透**，就是不让任何一面浮于表面。bewater 把双面性编码进每个核心产物的 schema 和每道门的检查（§9.1、§6.1）。

### 2.2 流动 Flow —— 假设驱动，边流边改

死水会腐，活水长流。创新不是瀑布（"收完所有事实再综合"），而是流动：**边研究边形成洞察，边验证边修正方向**。驱动流动的是"假设"——

> 不追求"证明自己对"，追求"最快学到哪里可能错"。从 *being right* 到 *learning quickly*。

用"假设 + 实验"持续降低不确定性，像水流不断冲刷河床。落到操作上：研究计划是**活的**（每周迭代四问，§9.2），不是一份写好就不动的甘特图。

### 2.3 适应 Adapt —— Strategy = Choice，方法随命题成形

> "把水倒进杯子，它就成了杯子；倒进瓶子，它就成了瓶子。"

方法本身是无形的骨架，但会**随具体命题而成形**——它可以是激进的新业务，也可以是温和的现有业务优化，形状由命题决定。而"成形"的关键是**选择**：

- **策略是一组选择，不是一份计划。** 大战略已死——战略选择比战略计划更重要。
- **策略陈述是"砍选择的刀，不是摘要"**（§9.5）。任何概念、任何功能决策都要过它这一关。它不总结全部，只代表那道最锋利的选择。

### 2.4 分流 Branch —— 广发散、窄收敛、多支并行

一条河遇到地势会分叉成多条支流，再在下游汇聚。创新同样：在机会域里**广发散**出大量早期概念（10–15 个），让它们各自独立验证（多条支流 = 多个小赌注，对冲不确定性），再 kill / 合流 / 推进，**窄收敛**到少数方案。

```
10–15 概念（广发散）
   ↓ 每条支流独立做假设地图 + 实验（并行验证）
三种去向：
   ├─ KILL（实验证伪，廉价砍）
   ├─ 合流（多条概念汇聚成一个方案）
   └─ 推进（评分卡高分，独立发展）
   ↓
2–4 方案（并行发展）→ 收敛聚焦
```

- **目的**：用多个小赌注替代一个大赌注，对冲不确定性。
- **纪律**：广发散是手段，窄收敛才是纪律（10–15 → 5 → 2–4 → 通常 1 个主推），不是无限分支。

### 2.5 成势 Momentum —— 归纳 + 消除法，汇聚成势

滴水可以穿石，水聚可以成势、可以载舟。我们**无法"证明"一个未来策略**，只能不断排除错误选项、积累证据，让信心一砖一瓦垒成势——最终把方案做成"**让人无法不投**（make it impossible not to invest）"，并在 Launch 后汇聚成持续的增长飞轮。

- **归纳推理 + 消除法**：不追求演绎证明，追求用证据排除选项、建立信心。
- **前置最危险的假设**：用最便宜的实验、最先测最致命的假设（致命弱点 Achilles Heel，§9.8），避免"做到最后才发现底子错了"。

> 渗透 → 流动 → 适应 → 分流 → 成势：从**深入两面**，到**持续修正**，到**选择成形**，到**多支对冲**，到**汇聚成势**。五性一体。

## 3. 核心模型

### 3.1 4 模块 × 8 Stage —— 主框架

每个 Stage 回答**一个且只回答一个**核心问题。一个 Stage 完成的标志不是"活动做完了"，而是**出口产物达到目标状态**。

| 模块 | Stage（中文释义 · English） | 核心问题 | 输入 | 输出（出口产物） |
|---|---|---|---|---|
| **Start** 目标对齐 | Immersion（目标对齐 target alignment） | 命题、目标、约束是什么？ | 模糊命题 | 项目章程 + 初始假设 |
| **Strategy** 战略定位 | Discover（发现洞察 Discover insight） | 事实和洞察是什么？ | 模糊命题 | 方向性假设 |
| | Define（战略定义 Define strategy） | 在哪赢、怎么聚焦？ | 洞察 / 假设 | 创新策略 + 机会域 |
| **Concept** 概念创新 | Ideate（探索概念 Ideate concept） | 有哪些可能方向？ | 策略 + 机会域 | 概念组合 |
| | Shape（方案定义 Shape solution） | 哪个方案值得投？ | 概念组合 | 方案 + 商业案例 |
| **Realization** 落地实现 | Design（设计方案 Design solution） | 完整体验和架构长什么样？ | 已验证方案 | 方案规格 |
| | Build（系统构建 build system） | 如何高质量造出来？ | 方案规格 | 可发布系统 |
| **Operation** 市场运营 | Launch（部署发布 Launch market） | 如何进入市场、建立动能？ | 可发布系统 | 上线 + 初始动能 |
| | Grow（增长 grow sustain） | 如何形成飞轮并持续？ | 上线 + 市场数据 | 增长洞察 |

### 3.2 四道门 + 五出口

**门的本质：资源分配决策点，不是质量检查点。** 不确定性递减、投入递增，所以分批下注——每过一门解锁下一量级资源。

| 门 | 位置 | 决策问题 | 性质 |
|---|---|---|---|
| **G1 战略门** | Define → Ideate | 这个方向值得投入探索资源吗？ | 判断题：定性为主，容忍高不确定，筛方向性错误 |
| **G2 概念门** | Shape → Design | 概念被验证到值得投入建设资源了吗？ | 举证题：全流程最重，本质是立项决策 |
| **G3 发布门** | Build → Launch | 达到进入市场的标准了吗？ | 清单题：readiness check，标准最硬、形式最轻 |
| **G4 经营评审** | Grow 段周期性 | 继续投入 / 维持收割 / 退役？ | 生命周期决策，外环入口 |

**统一五要素**：决策问题 / 证据要求（哪些产物达到什么状态）/ 单一 accountable 决策人 / **五出口**（Go · Conditional Go · Recycle · Pivot · Kill）/ 决策后动作（资源解锁、基线化、归档）。
**时机**：事件驱动为主（证据齐了申请评审）+ 时间盒兜底（到期强制触发，证据不齐本身就是决策依据）。

> ⚠️ 门不是官僚审批，是"收敛的纪律"。过了门才解锁下一量级资源，但**带标签不等于不可回溯**——后段发现根假设错，照样走大循环回前段（§3.3）。

### 3.3 三种循环（骨架线性，行为迭代）

| 循环 | 范围 | 治理 | 触发 |
|---|---|---|---|
| **小循环 · 迭代** | 模块内 / 相邻 Stage（Design↔Build、Ideate↔Shape） | 不经过门，是工作节奏 | 常态 |
| **大循环 · 回退** | 跨模块向上游 | **必须经过原门重新裁决** | 已验证的前提失效 |
| **外环 · 代际** | Grow(vN) → Discover(vN+1) | 新一代立项 | 增长洞察中的结构性洞察 |

- **小循环边界 = 已验证基线**：怎么迭代都行，一旦触碰已被门确认的内容，性质升级为大循环，必须上报。
- **大循环路由 = 回溯深度 = 假设错的深度**：失效沿产物血缘传播，回退到最上游被击中的**决策点**。详见 §6.2。

### 3.4 发散与收敛 + 分支组合

- **每 Stage 都是"先发散、再收敛"**（双面节奏）：广收集 → 炼成结论。**收敛 = 选择 = 灵魂**。
- **分支组合（Ideate → Shape 的空间结构）**：每个机会域广发散 → 10–15 概念 → 各自独立挂假设子集、并行验证 → 三去向（KILL / 合流 / 推进）→ 2–4 方案 → G2 收敛到 1–2 个。见 §2.4。

### 3.5 双面性与双重学习环

- **双面性**：每个核心产物（假设、概念、方案、规格）都要过 Money + Magic 双面检查（§9.1）。
- **双重学习环**：
  - **第一环 · 让产品变好**：Grow 的市场反馈 → 修正假设账本 → 增长洞察 → 下一代 Discover。每一代站在被市场检验过的认知上。
  - **第二环 · 让做产品的能力变好**：项目复盘的方法洞察 → 修订版本化的模板库 → 组织级先例库。方法论自身是活的。

### 3.6 4C 导航 —— 研究的四个方向

不是资料桶，是**要回答的四个问题**（Discover 阶段的骨架）：

| C | 提问 | 研究类型 |
|---|---|---|
| **Consumer 消费者** | 谁在买？为什么？ | 设计研究（共情） |
| **Company 公司** | 我们手里有什么？ | 干系人访谈 |
| **Category 品类** | 我们在哪个赛道玩？ | 市场研究 |
| **Channel 渠道** | 走什么渠道？ | 市场研究 |

> ⚠️ 4C 是"导航罗盘"，不是"四个抽屉"——目的是确保研究不瘸腿。§9.2 给出方法矩阵。

## 4. 名词定义（Glossary）

> 格式：**定义** ｜ 不是什么 ｜ 何时出现

**流程术语**
- **Immersion（目标对齐 target alignment）**｜Start 模块。内外对齐命题、范围、约束，播下初始假设。｜不是走形式 kickoff。｜前置。
- **Discover（发现洞察 Discover insight）**｜Strategy 模块。用 4C 深度探索，产出事实、洞察、方向性假设。｜不是漫无目的调研，是有学习计划的定向探索。
- **Define（战略定义 Define strategy）**｜Strategy 模块。把洞察炼成创新策略和机会域的"分流闸"。｜不是总结报告，是做战略选择。枢纽。
- **Ideate（探索概念 Ideate concept）**｜Concept 模块。基于机会域生成大量早期概念，再用标准收敛。｜不是头脑风暴完就完，是有 8 条标准把关。
- **Shape（方案定义 Shape solution）**｜Concept 模块。把选中概念发展成带商业案例的完整方案，"让人无法不投"。｜不是概念的简单细化。
- **Design（设计方案 Design solution）**｜Realization 模块。把已验证方案展开成完整体验与架构规格。｜不是重新发明概念，是高保真展开。
- **Build（系统构建 build system）**｜Realization 模块。按规格高质量构建可发布系统。｜不是无纪律的敏捷，要守已验证基线。
- **Launch（部署发布 Launch market）**｜Operation 模块。进入市场、建立初始动能。｜不是交付即结束，发布即验证。
- **Grow（增长 grow sustain）**｜Operation 模块。形成增长飞轮、持续迭代、代际交接。｜不是被动运维，是主动增长 + 外环学习。

**决策与知识术语**
- **Money + Magic**｜见 §2.1。商业敏锐 ∩ 消费者共情。
- **4C**｜Consumer / Company / Category / Channel（见 §3.6）。｜不是资料桶，是要回答的问题。
- **Fact vs Insight**｜Fact = 观察；**Insight = "一句非显而易见的话，为问题投下新光、帮我们生成方案"**。｜不是 Fact / 常识 / 共识 / 猜测。逻辑顺序：facts → insights → hypotheses。
- **Insight 四标准**｜Fresh（新鲜）/ Potent（有力）/ Energizing（激发）/ Truth（真实）。**F/P/E/T**。
- **方向性假设（Strategic Hypothesis）**｜"对创新策略可能是什么的一个有依据的猜测"。｜不是最终策略，是待验证的猜测。｜Discover 末 → Define。
- **创新策略（Innovation Strategy）**｜"在增长空间中识别可赢机会的一组选择"。｜Define。
- **策略陈述（Strategy Statement）**｜策略的"一句话把手"，代表核心选择。｜不是摘要，是锋刃（用来砍选择）。
- **机会域（Opportunity Areas, OA）**｜连接策略和概念的桥梁；2–4 个离散创新方向。｜不是功能模块，是创新机会。
- **概念（Notion）**｜早期、原始、provocative 的概念种子（"画之前的草图"）。｜不是方案、不是成品、不是保证（"允许错"）。｜Ideate。
- **概念的海拔（altitude）**｜概念的粒度。判断标准：什么高度对预测试最有用。
- **健康的焦虑（Healthy anxiety）**｜好概念应引发的焦虑感（够大吗？够大胆吗？搞得定吗？）。太安全 = 砍。
- **方案（Solution）**｜sharply-defined 的双面概念，含商业案例 / 财务 / 设计 / 叙事。｜Shape。
- **方案规格（Solution Spec）**｜体验规格 + 架构规格 + 实施计划，derived_from 已验证方案。｜Design。
- **可发布系统（Release Candidate）**｜可上线系统 + 发布包（部署 / 回滚 / 监控）。｜Build。
- **假设地图（Assumption Map）**｜识别概念 / 方案背后关键假设并排序。
- **致命弱点（Achilles Heel）**｜**高影响 × 高不确定**的假设——若错则击垮商业模式、且最没把握；必须先测。
- **假设账本（Assumption Ledger）**｜全项目维护的活假设表：内容 / 层级 / 影响面 / 不确定度 / 验证状态 / 证据强度。
- **证据强度六级**｜L1 主观判断 → L2 二手/类比 → L3 自陈意图（问卷）→ L4 行为信号 → L5 真实付费 → L6 可重复结果。致命弱点须 L4+。
- **投资叙事（Investment Narrative）**｜向决策层汇报的完整叙事，6 部分。｜Shape 交付物。
- **商业案例（Business Case）**｜财务可行性论证，用有依据的假设。
- **五出口**｜门的五种决策结果：Go / Conditional Go / Recycle / Pivot / Kill。
- **已验证基线**｜已被门确认的前提集合；小循环可自由迭代，触碰基线即升级大循环。
- **学习计划（Learning Plan）**｜动态研究计划，每周迭代四问。
- **知识库（Knowledge Base）**｜全流程共享的活知识库，沉淀原始素材与代际洞察，可回查。｜贯穿。

# Part II · 实操 Playbook

## 5. 流程 Playbook（Start + 4 模块 × 8 Stage）

> 每个 Stage 统一五要素：**定位 / 关键活动·工具 / 产出（内部链）/ 交接（handoff）/ 判断标准** + 人机分工。模板细节见 §9。

### 5.0 Immersion 目标对齐 —— Start：对齐命题，播下假设的种子

**定位**：Start 模块。内外 kick-off，对齐目标 / 范围 / 约束，写出项目章程，播下第一批初始假设。

**关键活动 · 工具**：
- 干系人访谈：摸清"为什么做、成功的样子、不能碰的红线"。
- 写**项目章程**（§9.1）：一句话命题（who / what / how / why）+ 范围 + 约束 + 成功标准。
- **播下种子假设**：把命题里最不确定的几条，写成待验证假设（哪怕粗糙），交给 Discover。

**产出**：项目章程 + 初始假设清单。

**交接**：项目章程 + 初始假设（传给 Discover，定义探索方向）。

**判断标准**：各方对"命题与成功标准"达成一致；初始假设 ≥3 条。

**人机分工**：AI 起草章程 / 整理干系人输入｜人锁定命题与成功标准。

---

### ▌ 决策段（Strategy + Concept）—— 管理不确定性

### 5.1 Strategy · 战略定位

#### 5.1.1 Discover 发现洞察 —— 穿越迷雾，把事实炼成洞察

**定位**：Strategy 模块。用 4C 定向探索，产出事实 + 洞察，收口为方向性假设。

**关键活动 · 工具**：
- **4C 研究方法矩阵**（一手 / 二手 × 四问，§9.2）：

  | C | 一手（Primary） | 二手（Secondary） |
  |---|---|---|
  | Consumer | 情境访谈 · 陪同购物 · 日记研究 · 焦点小组 · 拦截 · 问卷 | 趋势报告 · 社媒 / 博客 · 公司数据 |
  | Category | 实地考察 · 专家访谈 | 市场报告 · 竞品审计 · 类比案例 |
  | Channel | 沉浸式考察 · 专家访谈 | 标杆扫描 |
  | Company | 干系人访谈 · 现场走访 · 工作坊 | 公司数据 |

- **活的学习计划**（§9.2）：每周迭代四问。
- **主题聚类** → **Fact → Insight 升级**（洞察评判卡 F/P/E/T，§9.3）。

**产出（内部链，insight 连续形成）**：
```
研究执行 → 每日复盘 → 非结构化简报 → 主题聚类 → 洞察（F/P/E/T）→ 方向性假设（§9.4）
```

**交接**：**方向性假设**（收敛物，传给 Define）。原始素材进知识库留底。

**判断标准**：洞察过 F/P/E/T；能区分 fact 和 insight；4C 不瘸腿。

**人机分工**：AI 桌面研究 / 聚类 / fact→insight 候选 / 访谈大纲｜人守真人访谈（共情）、判断哪条 insight 够 F/P/E/T。

---

#### 5.1.2 Define 战略定义 —— 把洞察炼成选择（分流闸）

**定位**：Strategy 模块，整个方法的**枢纽**——产出创新策略 + 机会域，决定下游一切。

**关键活动 · 工具**：
- **洞察碰撞**：用方向性假设模板（§9.4）把多个洞察组合成假设。
- **策略制定**：写策略陈述（§9.5，两种写法 + 标杆 + 反例）。
- **机会域划分**：用 4 种组织战术（§9.6）。

**产出**：方向性假设 → **创新策略 + 策略陈述** → **2–4 个机会域**。

**交接**：**创新策略 + 机会域**（传给 Ideate，定义发散边界）。策略陈述作为"过滤器"贯穿后续所有阶段。

**判断标准**：策略回答"哪个机会能赢"而非"在哪玩"；机会域边界互不重叠、各自能 spawn 多个概念。

**人机分工**：AI 洞察碰撞生成假设 / 4C 填充 / 策略陈述候选｜人选哪个策略。

> 🚪 **G1 战略门（判断题）**：策略陈述锁定了吗？机会域是 2–4 个、互不重叠吗？Money+Magic 双面初判成立吗？假设账本完成初始盘点、致命弱点象限已识别吗？过门才进 Ideate。

---

### 5.2 Concept · 概念创新

#### 5.2.1 Ideate 探索概念 —— 在机会域里广发散，用标准窄收敛

**定位**：Concept 模块。基于机会域发散大量早期概念，再用标准收敛。

**关键活动 · 工具**：
- **发散**：每个机会域用 brainstorm + "how might we"，用概念捕获模板（§9.7，8 字段）。
- **评估**：跑 8 条标准（§9.7）+ 组合策展矩阵（§9.7 评分卡）。

**产出**：10–15 个概念（名称 + 一句话）→ 选 5 个填完整模板 → 收敛到 2–4 个。

**交接**：**概念组合（2–4 个）**（传给 Shape）。全部概念存档可回溯。

**判断标准**：≥3 个能 5 词以内表达；≥2 个引发健康焦虑；全部过策略陈述过滤器。

**人机分工**：AI 发散 20–30 概念 / 填卡 / 跑 8 标准 / 起强名｜人收敛选择、感知健康焦虑、定海拔。

> 概念收敛检查点（Ideate → Shape，轻量自评，不设大门）：≥3 个 5 词表达、≥2 个引发健康焦虑、全部过策略陈述过滤器。

---

#### 5.2.2 Shape 方案定义 —— 测致命弱点，做成"无法不投"

**定位**：Concept 模块。把选中概念发展成带商业案例的完整方案。

**关键活动 · 工具**：
- **概念 → 方案五路径**：线性细化 / 转向（Pivoting）/ **合流**（合并多概念）/ 新发明 / 范围扩展。
- **优化两种模式**：现有业务（测概念，2–3 周）/ 新业务（测假设，~6 周 3 周期）。
- **假设驱动实验 4 步**（§9.8）：识别 → 聚焦致命弱点 → 真实行为测试 → 必要时重复。实验菜单见 §9.9。
- **叙事**：投资叙事 6 部分（§9.10）+ 财务案例（§9.10）。

**产出**：优化计划 + 实验 findings → **方案 + 商业案例 + 投资叙事**（+ 原型）。

**交接**：**方案 + 投资叙事**（给 G2 决策层 / Design）。

**判断标准**：方案三件事——**聚焦 / 详尽 / 有说服力**（Focused / Detailed / Persuasive）；"让人无法不投"。

**人机分工**：AI 假设地图 / 实验设计 / 二手实验执行 / 财务建模｜人一手实验、Kill / Proceed 决策。

> 🚪 **G2 概念门（举证题，全流程最重）**：致命弱点全部有验证结论、证据 ≥ L4 真实行为级吗？财务案例每条假设挂证据吗？投资叙事 6 部分齐、双面成立吗？终极标准："让人无法不投"。过门解锁建设资源；决策后假设账本基线化（日后判断"战略前提是否被市场推翻"的参照物）。

---

### ▌ 执行段（Realization + Operation）—— 管理确定性交付

### 5.3 Realization · 落地实现

#### 5.3.1 Design 设计方案 —— 概念意图的高保真展开

**定位**：Realization 模块。把已验证方案展开成完整体验与架构规格，可开工。

**关键活动 · 工具**：
- **体验设计**：用户旅程、关键界面、服务蓝图。
- **技术架构**：架构决策记录入决策日志（ADR，§9.11）。
- **概念意图保真检查**：每个重大取舍对照已验证方案与策略陈述，防止"执行漂移"。

**产出 · 方案规格（Solution Spec）**：体验规格 + 架构规格 + 实施计划。血缘 derived_from 已验证方案。

**交接**：方案规格传给 Build（同团队时为轻交接）。

**判断标准**：规格完整可开工；重大设计取舍有决策记录；**未触碰已验证基线**（触碰即上报大循环）。

**人机分工**：AI 原型生成 / 规格起草 / 一致性检查（Spec vs 方案的偏离检测）｜人体验与架构品味决策、基线越界裁决。

---

#### 5.3.2 Build 系统构建 —— 敏捷承接，纪律守界

**定位**：Realization 模块。按规格高质量、可持续地造出可发布系统。

**关键活动 · 工具**：
- **敏捷开发**：sprint 节奏属于团队，方法论不规定。
- **Design↔Build 小循环**：体验问题回 Design 迭代（不触基线随便迭）。
- **质量工程**：测试、性能、安全。
- **发布准备**：G3 清单逐项达成。

**产出 · 可发布系统（Release Candidate）**：可发布系统 + 发布包（部署方案、回滚预案、监控配置）。

**交接**：可发布系统交 G3；**Launch 交接**（第二重的交接）：含产品逻辑、目标用户画像、开放假设（上市后继续观察什么）交给市场 / 运营。

**判断标准**：G3 清单全绿（大部分自动化核验）。

**人机分工**：AI 编码加速 / 测试生成 / 文档起草｜人工程判断、发布拍板。

> 🚪 **G3 发布门（清单题）**：质量达标（测试 / 性能 / 安全全绿）？GTM 就绪（渠道 / 定价 / 物料、运营承接确认）？回滚预案与监控就位？二元判断，不留模糊空间。过门进 Launch。

---

### 5.4 Operation · 市场运营

#### 5.4.1 Launch 部署发布 —— 进入市场，建立初始动能

**定位**：Operation 模块。进入市场、建立初始动能。**发布即验证**——发布本身是一次大型 validation，市场数据开始流入假设账本。

**关键活动 · 工具**：
- **GTM 执行**：渠道、定价落地、种子客户。
- **发布监控**：技术指标 + 业务指标双看板。
- **快速响应循环**：发布期问题的小循环处理。

**产出 · 上线报告（Launch Report）**：初始市场反应（激活 / 转化 / 留存首数据）+ 假设初检结果 + 问题清单。

**交接**：上线报告传给 Grow；运营承接确认。

**判断标准**：初始动能指标达到章程定义的发布成功判据；重大市场信号已结晶入账本。

**人机分工**：AI 发布内容生成 / 数据日报 / 异常解读｜人 GTM 决策、危机处理。

---

#### 5.4.2 Grow 增长 —— 增长飞轮与代际交接

**定位**：Operation 模块。形成增长飞轮、持续迭代，并完成代际交接。**这里是大循环的高发区**——上市前所有假设面对真实数据的持续审判。

**关键活动 · 工具**：
- **增长实验**：AARRR 漏斗逐环优化，每个实验就是一次 validation。
- **假设账本的市场化检验**：真实数据持续审判上市前假设。
- **G4 经营评审**（季度）：继续投入 / 维持收割 / 退役。
- **增长洞察提炼**（与洞察报告同构）。

**产出 · 增长洞察（Growth Insight）**：什么在起作用（飞轮识别）/ 什么假设被市场修正 / **渐进优化项**（留本代持续迭代）vs **结构性洞察**（现有框架装不下的新信号 → 触发下一代立项）。

**交接**：**外环**——结构性洞察成为下一代 Immersion / Discover 输入；本代持续运营或按 G4 决议退役。

**判断标准**：飞轮有数据证据；结构性洞察与渐进优化被明确区分。

**人机分工**：AI 增长实验设计与分析 / 洞察草稿 / 飞轮建模｜人 G4 裁决、结构性 vs 渐进的判断、增长策略选择。

> 🚪 **G4 经营评审（Grow 段，季度）**：三出口——继续投入 / 维持收割 / 退役；同时裁定增长洞察中的结构性洞察是否触发下一代立项（外环入口）。

## 6. 治理与节奏

### 6.1 四道门判据清单

**G1 战略门**（Define → Ideate）｜决策人：产品负责人级
- [ ] 洞察经人签署过 F/P/E/T
- [ ] 方向性假设收口 2–5 条，双面结构完整
- [ ] 策略陈述锁定，通过"是刀不是摘要"检测（反例：术语堆砌 / 重述简报）
- [ ] 机会域 2–4 个，互不重叠，各自能孵出多个概念
- [ ] 假设账本完成初始盘点，致命弱点象限已识别（不要求已验证）
- [ ] Money + Magic 双面初判成立

**概念收敛检查点**（Ideate → Shape，轻量自评，不设大门）
- [ ] ≥3 个概念 5 词以内表达；≥2 个引发健康焦虑（人工判断项）
- [ ] 全部通过策略陈述过滤器

**G2 概念门**（Shape → Design）｜决策人：投资决策级（最高层级）｜**全流程最重**
- [ ] 方案达到 validated 状态
- [ ] **致命弱点全部有验证结论，证据强度 ≥ L4 真实行为级**（自陈意愿不算数）
- [ ] 财务案例每条假设挂证据（标来源与逻辑）
- [ ] 投资叙事 6 部分齐备；双面成立
- [ ] 终极标准："make it impossible not to invest"
- [ ] 决策后动作：假设账本基线化（日后判断"战略前提是否被市场推翻"的参照物）

**G3 发布门**（Build → Launch）｜决策人：发布负责人｜大部分自动核验
- [ ] 质量达标（测试 / 性能 / 安全清单全绿）
- [ ] GTM 就绪（渠道 / 定价 / 物料）；运营承接文档就绪并已确认接收
- [ ] 回滚预案与监控配置就位
- [ ] 二元判断，不留模糊空间

**G4 经营评审**（Grow 段，季度）｜决策人：业务负责人
- 三出口：继续投入 / 维持收割 / 退役；同时裁定结构性洞察是否触发下一代立项。

### 6.2 循环治理：失效传播 → 回溯深度

当一个验证结果证伪了某条假设，按"错的深度"决定回溯多远：

```
假设层级（由根到叶）：根前提 → 策略 → 机会域 → 概念 → 功能
                       ↑                                   ↑
                  错在这 → 回 Discover 重新发现      错在这 → 局部 reframe（小循环）
```

| 失效位置 | 回溯到 | 循环类型 | 成本 |
|---|---|---|---|
| 功能 / 概念（叶层） | 当前段内 reframe | 小循环 | 低 |
| 机会域 / 策略 | 回 Define，调机会域或策略 | 大循环（过 G1 重裁） | 中–高 |
| 根前提 | 回 Discover，重新发现 | 大循环（过 G1 重裁） | 高 |
| 上市后被市场推翻（Grow 段） | 回 Discover/Define，甚至下一代立项 | 外环 / 大循环 | 视深度而定 |

**原则**：
- **小循环边界 = 已验证基线**：怎么迭代都行，一旦触碰已被门确认的内容，性质升级为大循环，必须上报重裁。
- **回退路由 = 回到最上游被击中的决策点**（回溯深度 = 假设错的深度）。
- **宁可早回溯**（成本低），不可一条错路走到底。bewater 的设计就是把最危险的假设前置、低成本验证，正是为了"在还能改的时候发现错"。

### 6.3 反模式清单

| # | 反模式 | 症状 | 正解 / 防御 |
|---|---|---|---|
| 1 | **用执行思维管决策段** | 对探索工作要求排期与确定性 | 决策段度量假设验证速度，不度量交付进度 |
| 2 | **用决策思维管执行段** | Build 阶段无休止重议战略 | 小循环边界 = 已验证基线；越界走大循环仪式 |
| 3 | **只 Go 不 Kill** | 所有项目惯性滑到 Build | Kill 率做成组合健康度指标；G1/G2 应有明显淘汰率 |
| 4 | **Conditional Go 滥用** | 项目全部带病通过，条件从不闭环 | 未闭环 condition 阻塞下一门准入 |
| 5 | **单面倾斜** | 全 magic 没 money（自我感动）或反之（没人爱） | 产物双面区块非空校验 |
| 6 | **收完事实再综合（瀑布）** | 事实永远收不完，错过早期 insight | 边做边综合，活的学习计划 |
| 7 | **4C 瘸腿** | 只做 Consumer 不做 4C | 4C 四问都答（各 ≥3 条事实） |
| 8 | **洞察当事实 / 常识当洞察** | 洞察必须非显而易见 | 过 F/P/E/T 四标准 |
| 9 | **策略陈述写成摘要** | 摘要不能砍选择 | 写成"锋刃"——能砍掉方案的 |
| 10 | **无限分支不收敛** | 对冲不是发散 | 广发散 → 严格窄收敛 |
| 11 | **先测容易的而非致命假设** | 致命假设错了全盘皆输 | 先测高影响 × 高不确定（L4+） |
| 12 | **陈述意愿当验证** | "用户说愿意付钱"就过 G2 | G2 硬性要求真实行为级证据 |
| 13 | **AI 越权 converge** | 直接采纳"看似合理"的 AI 方案，跳过共情与判断 | 人不可让渡动作（§8.2）；收敛亲自来 |

## 7. 知识与交接机制

### 7.1 产物链与血缘（信息怎么流动）

不是"一个文档往下传、前面全丢"，而是三个机制配合：

| 机制 | 说明 |
|---|---|
| **① 收敛物 handoff** | 每段往下传**收敛后的结论**（假设 / 策略 / 概念组合 / 方案 / 规格），**不传原始研究堆**——否则下游被淹没 |
| **② 知识库留底** | 原始素材（录音 / 笔记 / 报告 / 实验数据）进全流程共享知识库，不全传也不丢，可回查 |
| **③ 核心策略贯穿** | 策略陈述、核心洞察作为"过滤器"被后续阶段反复引用，不是用一次就丢 |

> 比喻：**法院卷宗 vs 判决书**——传的是判决书（收敛结论），卷宗存档可查。呼应 §2.3 Strategy = Choice：传"这阶段的选择"，不传纠结过程。

**血缘**：每个产物标注"由哪些上游产物推导而来（derived_from）"。当上游某条洞察 / 假设被推翻，沿血缘找出所有受影响的下游产物，触发修复（§6.2）。两处关键交接：
- **G2 交接**（Shape → Design）：方案 + 投资叙事 + 开放假设。
- **Launch 交接**（Build → Launch）：产品逻辑 + 用户画像 + 上市后待观察假设（第二重交接，最易被忽视）。

### 7.2 假设账本与致命弱点

**假设账本**：全项目维护一张活的假设表——每条假设记录：内容 / 层级 / 影响面 / 不确定度 / 验证状态 / 证据强度。它是回溯治理（§6.2）和实验优先级（§5.2.2）的事实依据，也是 G2 后基线化、日后判断"战略前提是否被市场推翻"的参照物。

**证据强度六级**（由低到高）：

| 级别 | 证据类型 | 例子 |
|---|---|---|
| L1 | 主观判断 / 专家意见 | "我觉得用户会喜欢" |
| L2 | 二手数据 / 类比 | 行业报告、相似案例 |
| L3 | 自陈意图（问卷） | 问卷说"愿意买" |
| L4 | 行为信号（非真实交易） | 假网站注册、广告 CTR |
| L5 | 真实行为 / 真实付费 | 众筹下单、试销购买 |
| L6 | 持续的可重复结果 | 多轮实验稳定复现 |

> **致命弱点必须用 L4+ 的真实行为证据验证**，不能停在 L1–L3 的"嘴上说"。**Launch 后**，市场数据开始把大量假设从 L1–L3 推向 L4–L6——这是为什么"发布即验证"。

### 7.3 知识库与代际留底

- 原始素材（访谈录音 / 笔记 / 报告 / 实验数据）入知识库，打标签（4C / 阶段 / 主题）。
- 全程共享、可回查；交接时不传，但下游可随时调取。
- **外环学习**：Grow 段的增长洞察也入知识库，喂下一代 Immersion / Discover。被 kill 的分支不删除——其验证过的假设结论留在账本，继续服务其他分支。

## 8. 人机协作

**核心原则：AI 负责 diverge（发散），人负责 converge（收敛）**——而 converge = choice = 灵魂（§2.3）。

### 8.1 分工总表（8 Stage）

| Stage（中文释义） | AI 干（发散 / 加速） | 人守住（收敛 / 不可让渡） |
|---|---|---|
| Immersion 目标对齐 | 起草章程、整理干系人输入 | 锁定命题与成功标准 |
| Discover 发现洞察 | 桌面研究、聚类、fact→insight 候选、访谈大纲 | 真人访谈（共情）、判断哪条 insight 够 F/P/E/T |
| Define 战略定义 | 洞察碰撞生成假设、4C 填充、策略陈述候选 | 选哪个策略 |
| Ideate 探索概念 | 发散 20–30 概念、填卡、跑 8 标准、起强名 | 收敛选择、感知健康焦虑、定海拔 |
| Shape 方案定义 | 假设地图、实验设计、二手实验执行、财务建模 | 一手实验、Kill / Proceed 决策 |
| Design 设计方案 | 原型生成、规格起草、Spec↔方案偏离检测 | 体验与架构品味、基线越界裁决 |
| Build 系统构建 | 编码加速、测试生成、文档起草 | 工程判断、发布拍板 |
| Launch 部署发布 | 发布内容、数据日报、异常解读 | GTM 决策、危机处理 |
| Grow 增长 sustain | 增长实验设计与分析、洞察草稿、飞轮建模 | G4 裁决、结构性 vs 渐进判断、增长策略选择 |

### 8.2 人不可让渡的三件事

1. **判断选择**（converge = choice）：选哪条策略、砍哪个概念、kill 还是 proceed、G4 裁决。
2. **共情**（真人访谈）：真实的用户处境理解，AI 替代不了。
3. **品味直觉**：感知健康焦虑、判断概念海拔、辨别"非显而易见"的洞察、体验与架构品味。

### 8.3 头号陷阱

> AI 会诱惑你**跳过共情 / 判断，直接产出"看似合理"的方案**。

**铁律：AI 加速 diverge，但 converge 必须慢、亲自来。** 让 AI 一次生成 30 个概念很容易，但从 30 个里选出对的那个、并敢于 kill 掉"有意思但不对"的——这是人不可让渡的判断。把 converge 也丢给 AI，等于放弃了方法论的灵魂。

## 9. 模板工具箱（字段级）

> 每个 = 用途 / 字段 / 要点。流程里标注"用 §9.x"处即查此处。

### 决策段模板

**9.1 项目章程 + Money/Magic 双面定义**
- 项目章程：一句话命题（who/what/how/why）+ 范围 + 约束 + 成功标准。
- 双面定义字段：**Magic**（处境与渴望，⚠️ 写"处境和渴望"不是"能解决问题"）/ **Money**（商业逻辑：怎么成、怎么赚、怎么持续）/ **双面张力点**。
- 要点：单面倾斜是最常见的死法；Magic 不是"愿不愿买单"。

**9.2 4C 研究框架 + 学习计划**
- 4C：四问（Consumer/Company/Category/Channel），每格 ≥3 条事实（方法见 §5.1.1 矩阵）。
- 学习计划四问（每周迭代）：**已找到 / 未找到 / 待深挖 / 可放弃**（"未找到"是灵魂）。

**9.3 洞察评判卡（Fact → Insight → F/P/E/T）**
- Fact（原话/观察）→ Insight（一句非显而易见的话）→ 四标准自评：**F**resh / **P**otent / **E**nergizing / **T**ruth。
- 要点：insight ≠ fact ≠ 常识 ≠ 共识 ≠ 猜测；过不了四标准降回 fact。

**9.4 方向性假设（By / We can / Resulting in）**
- **By**[手段] / **We can**[客户价值=Magic] / **Resulting in**[业务收益=Money] + 4C 各一条洞察支撑（别瘸腿）。
- 要点：双面结构；是猜测不是结论。

**9.5 策略陈述（砍选择的刀）**
- 两种写法：① 捕捉 pivot insight（例「把流程带给创意」·某玩具巨头）② 捕捉 narrowed opportunity（例「赢下家居改造最后一公里」·某家居零售巨头）。
- 反例：术语堆砌（某工业巨头）、重述简报（某零钱兑换机品牌）。
- 要点：是砍选择的刀，不是摘要。能砍掉方案的才是好陈述。

**9.6 机会域组织战术**
- 4 种切法：按消费者原型 / 业务支柱 / 消费者需求 / 旅程阶段。
- 要点：2–4 个；互不重叠；是机会不是功能模块；每个能 spawn 多个概念。

**9.7 概念捕获卡（8 字段）+ 8 条标准 + 评分卡**
- 概念卡 8 字段：① 概念名（强占位名）② 消费者洞察 ③ 商业洞察 ④ What ⑤ Who ⑥ Why big ⑦ 一句话描述（≤5 词）⑧ 速写草图。
- 8 条标准：① 清晰 insight+tension ② 简单新产品独特解决 ③ who/what/does/replaces/why big ④ 5 词以内 ⑤ 足够具体 ⑥ 强名 ⑦ 对的可视化 ⑧ 设计原则。
- 组合策展矩阵：Money（策略对齐/规模/速度/风险/ROI）∩ Magic（未满足需求/颠覆/分层/可重复/达尔文）。砍掉"只有意思"的。

**9.8 假设地图 + 致命弱点**
- 假设分类：Consumer / Commercial / Technical / Distribution / Regulatory。
- 二维排序：影响面 × 不确定度。**致命弱点 = 高影响 × 高不确定 → 🔥 最先测**（优先 consumer-centric）。证据须 L4+。

**9.9 实验方法菜单**

| 方法 | 测什么 | 要点 |
|---|---|---|
| 假网站（Fake Website） | 注册意愿 | 测 sign-up 转化 |
| 社媒 A/B 测试 | 点击意愿 | CTR 基准 ~0.9% |
| 众筹（Crowdfunding） | 真实付费意愿（WTP） | L5 强证据 |
| 妈妈测试（Mom Test） | 真实行为（非观点） | 问"做过什么"不问"会不会" |
| 相关世界（Related Worlds） | 类比可行性 | 跨行业找先例 |
| 专家访谈 | 技术 / 监管可行性 | L2 |
| 价格敏感度（Van Westendorp） | 定价区间 | 测可接受价格带 |
| 游击访谈 | 快速行为信号 | 低成本广撒 |

> 原则：**Keep it simple + Define metrics**。实验前先定成功指标 + 基准，否则无法判 kill/proceed。

**9.10 投资叙事（6 部分）+ 财务案例**
- 投资叙事 6 部分：① Brief ② Opportunity ③ Solution ④ Why big ⑤ Financial Case ⑥ Roadmap。
- 财务案例（有依据的假设）：每条假设标来源/逻辑（项目数参照众筹同类、成功率参照行业 ~36%）；必含用户数/留存/定价/CAC/成本/逐年盈亏/盈利时间点。
- 要点：方案三件事——聚焦 / 详尽 / 有说服力；目标"让人无法不投"。

### 执行段模板

**9.11 方案规格（Solution Spec）+ 架构决策记录（ADR）**
- 方案规格 = 体验规格（旅程/关键界面/服务蓝图）+ 架构规格 + 实施计划；标注 derived_from 已验证方案。
- ADR：每个重大架构 / 体验取舍记一条（背景 / 决策 / 理由 / 后果），入决策日志。
- 要点：概念意图保真检查——每个取舍对照已验证方案与策略陈述，防执行漂移。

**9.12 发布门清单（G3 readiness）**
- 质量（测试/性能/安全全绿）+ GTM（渠道/定价/物料/运营承接确认）+ 回滚预案 + 监控配置。二元判断，逐项打钩。

**9.13 GTM（进入市场）**
- 渠道（在哪卖）/ 定价（怎么收，呼应财务案例）/ 冷启动（种子客户从哪来）/ 物料。落地 Shape 阶段的 GTM 设计。

**9.14 增长飞轮 + 增长实验**
- 飞轮：画出可复利的增长回路（AARRR：获客→激活→留存→变现→推荐），标出哪一环是当前杠杆点。
- 增长实验：每环假设 → 实验 → metric → kill/放大。每个实验即一次 validation。
- 增长洞察：明确区分**渐进优化项**（本代迭代）vs **结构性洞察**（触发下一代立项）。

## 10. 案例库（去品牌化）

> 每个标注：对应 Stage + 学什么。所有机构名已隐去，只演示方法。

### 10.1 策略陈述标杆（Define）

- **某玩具巨头**：「把流程带给创意」——捕捉 pivot insight（创意工作从"灵感随机"转向"可流程化"）。
- **某家居零售巨头**：「赢下家居改造的最后一公里」——捕捉 narrowed opportunity。
- **反例 · 某工业巨头**：堆术语，砍不掉任何方案。
- **反例 · 某零钱兑换机品牌**：只是重述简报，不是选择。

### 10.2 概念标杆（Ideate）

- **某咖啡甜甜圈连锁「疏导车流」**：强占位名 + 关联明确洞察（高峰车流拥堵）+ 5 词表达。学"概念卡 8 字段"怎么填得锋利。

### 10.3 完整链路标杆：某银行循环经济（Define → Shape）

4C 探索 → 8 个机会域（如「循环压力测试」）→ 评分卡六维打分 → 假设测试 → 三层时间窗映射（H1 短期 / H2 中期 / H3 长期）。**学完整决策段链路 + 评分卡用法。**

### 10.4 投资叙事范本：某消费品巨头「A 项目」（Shape）

投资叙事 6 部分 + 财务案例：项目数 250→7500、成功率 20%→30%、第 5 年利润 £5.4m、3–4 年盈利。每条假设标来源。**学商业案例建模。**

### 10.5 实验 + 方案：某保险巨头「翻转」（Shape）

2 个周期：8 个深访 + 1200 份问卷 + 3 个社交广告测定价。**学实验怎么低成本跑出真实行为证据（L4–L5）。**

### 10.6 本土全链路主线：「The Operator · 创作者裁判」⭐（Immersion → Grow）

## 12. 度量与 FAQ

### 12.1 度量体系

| 维度 | 指标 | 健康信号 |
|---|---|---|
| **假设降险（决策段）** | 致命弱点验证数 / 假设总数；证据强度分布 | 致命假设达 L4+；不堆 L1–L3 |
| **收敛纪律** | 发散数 → 收敛数比（如 15→3） | 有收敛，非无限分支 |
| **Kill 健康度** | G1/G2 的淘汰率 | 有明显淘汰，非全部惯性滑到 Build |
| **回溯健康度** | 回溯次数 / 阶段；回溯深度分布 | 早回溯（叶层）多、晚回溯（根层）少 |
| **双面成立** | 产物过 Money+Magic 双面检查的比例 | 双面都成立，无单面倾斜 |
| **交付（执行段）** | 门到门周期；G3 清单通过率；缺陷逃逸率 | 门不堵塞、不跳门；质量前置 |
| **发布动能** | 激活 / 转化 / 留存首数据 vs 章程判据 | 达到发布成功判据 |
| **飞轮** | AARRR 各环转化；杠杆环识别 | 有可复利回路，非一次性 |
| **外环学习** | 每项目沉淀的增长洞察数 → 喂回下一代 | 知识库在增长，代际谱系建链 |

### 12.2 FAQ

**Q1：8 Stage 必须线性走完吗？**
不必。线性是骨架（保证交付），但 Stage 内高频小循环、Stage 间允许大循环回溯（§3.3、§6.2）。回溯深度由假设错的深度决定。

**Q2：决策段和执行段为什么必须分开管？**
两段管理对象不同：决策段管不确定性（度量假设验证速度，Kill 是成功），执行段管确定性交付（度量交付速度与质量，摇摆战略是浪费）。混管是最常见的组织失配（§1.2、§6.3 反模式 1/2）。

**Q3：小团队 / 个人跑得起吗？**
能。最小流程见 §11——4C 可轻量化（3–5 真人访谈）、模板照填、实验用最便宜的（假网站 / 游击访谈）。重在内核（假设驱动 + 双面 + 发散收敛 + 决策/执行分治），不在仪式。

**Q4：和精益创业 / 双钻什么关系？**
同源不同名（见 §1.4 映射表）。bewater 的特点：① 决策/执行分治（4 模块 × 8 Stage）② Money+Magic 双面性作为硬约束 ③ 策略陈述作为贯穿过滤器 ④ 假设分层 + 致命弱点前置 + 证据六级 ⑤ 概念层用水的隐喻做哲学记忆抓手。

**Q5：AI 能替我跑到哪一步？**
发散 / 加速段（桌面研究、生成概念、填卡、实验设计、编码、测试、数据日报）AI 大幅加速；收敛段（选策略、砍概念、kill/proceed、G4 裁决、真人共情）必须人来（§8）。铁律：AI 加速 diverge，converge 亲自来。

**Q6：策略陈述总写不好怎么办？**
常见病：写成摘要、堆术语、重述简报。检验法：**它能不能砍掉至少一个候选方案？** 砍不掉 = 它不是锋刃。参照 §9.5 标杆与反例。

**Q7：实验做了但无法判断 kill/proceed？**
多半是实验前没定成功指标 + 基准（§9.9 铁律）。补救：回退一步，先定"什么结果 = proceed / 什么 = kill"，再补实验。

**Q8：Build 阶段又想改战略怎么办？**
先问：是不是触碰了已验证基线？若是，停下——这是大循环，必须回原门（G2 甚至 G1）重裁，不能在 Build 阶段偷偷改（§6.3 反模式 2）。若只是实现手段（不触策略陈述），属小循环，随便迭。
